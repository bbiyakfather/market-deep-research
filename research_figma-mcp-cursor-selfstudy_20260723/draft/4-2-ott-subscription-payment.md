# 4-2. 프로젝트: OTT 구독 스타일 웹 (결제)

넷플릭스 같은 화면을 만드는 것까지는 디자인의 영역입니다. 이 페이지는 그다음, 대부분의 튜토리얼이 얼버무리는 부분을 다룹니다. "구독하기" 버튼을 누르면 실제로 결제창이 뜨고, 매달 자동으로 결제되는 흐름입니다. 실제 돈은 한 푼도 쓰지 않고, 사업자등록 없이 전부 연습할 수 있습니다.

---

## 1. 완성 목표와 선수지식

**이 프로젝트가 끝나면 손에 남는 것**

1. 콘텐츠 목록 페이지 — 영화·드라마 포스터가 격자로 깔린 화면
2. 단건 결제 — "구독하기" 버튼 → 결제창 → 테스트 결제 성공 페이지 도착
3. (심화) 구독 결제 — 카드를 한 번 등록하면 이후 자동으로 결제되는 흐름의 뼈대

**선수지식**

- 앞 단계에서 만든 개발 환경: Cursor(AI 코드 에디터) 설치와 프로젝트 폴더
- HTML·CSS가 "화면을 그리는 언어"라는 정도의 감각 — 문법 암기는 불필요합니다
- 사업자등록·카드·돈: **전부 필요 없습니다.** 이 페이지의 모든 실습은 무료 테스트 환경에서 진행됩니다

참고로 인프런의 유료 강의 [Supabase로 웹사이트 3개 클론하기](https://www.inflearn.com/course/%EC%9A%94%EC%A6%98%EC%97%94-supabase-%EB%8C%80%EC%84%B8%EC%A7%80-nextjs-%ED%81%B4%EB%A1%A0%ED%94%84%EB%A1%9C%EC%A0%9D%ED%8A%B8)가 넷플릭스 화면 클론을 다루지만, 결제(구독) 기능 포함 여부는 강의 소개에서 확인되지 않습니다. 결제는 이 페이지의 경로로 배우는 것이 확실합니다.

---

## 2. 결제 개념 3분 — PG·결제위젯·빌링키

코드를 만지기 전에 단어 세 개만 잡고 갑니다.

| 용어 | 한 줄 풀이 | 비유 |
|---|---|---|
| PG(지급결제대행사) | 내 서비스와 카드사·은행 사이에서 결제를 대신 처리해 주는 회사 | 카드사 수십 곳과 일일이 계약하는 대신, 계약 한 번으로 끝내주는 중개인. 토스페이먼츠가 여기에 해당합니다 |
| 결제위젯 | PG가 미리 만들어 둔 결제 화면 부품. 몇 줄 코드로 내 페이지에 끼워 넣습니다 | 조립식 무인 계산대 — 카드·간편결제 버튼이 이미 다 달려 있습니다 |
| 빌링키 | 정기결제용 열쇠. 고객 카드번호는 PG가 보관하고, 나는 "이 카드로 결제해 줘"라고 요청할 열쇠만 받습니다 | 헬스장 자동이체 동의서 — 매달 카드번호를 다시 물어보지 않아도 되게 하는 등록증 |

하나 더, 결제가 **두 단계**라는 점이 중요합니다. 브라우저에서 결제창으로 "요청"하고, 내 서버가 금액을 검증한 뒤 "승인"해야 결제가 완료됩니다. 브라우저 쪽 코드는 사용자가 조작할 수 있어서, 최종 확인은 반드시 서버가 하도록 [공식 문서](https://docs.tosspayments.com/guides/v2/payment-widget/integration)가 설계해 둔 것입니다.

## 3. 토스페이먼츠 테스트 환경 만들기

**[무엇을 배우나]** 실제 돈이 오가지 않는 연습용 결제 환경을 만듭니다.

**[왜 필요한가]** 결제는 계약과 심사가 필요한 영역이라 "그냥 해보기"가 어려워 보이지만, 토스페이먼츠는 학습용 입구를 따로 열어 두었습니다. 이메일·전화번호만으로 개발자센터에 가입하면 사업자등록 없이 결제 테스트, API(프로그램끼리 요청을 주고받는 창구) 로그 확인, 웹훅(결제 결과를 내 서버로 알려주는 자동 알림) 설정까지 가능합니다.

**[따라하기]**

1. [회원가입, 사업자번호 없이 결제 테스트하기](https://docs.tosspayments.com/blog/how-to-test-toss-payments) 안내에 따라 개발자센터에 가입합니다.
2. [환경 설정하기](https://docs.tosspayments.com/guides/v2/get-started/environment) 문서를 보고 테스트용 **클라이언트 키**(브라우저에서 쓰는 공개 열쇠)와 **시크릿 키**(서버에서만 쓰는 비밀 열쇠)를 확인해 메모합니다.
3. 테스트 환경의 성질을 알아 둡니다.
   - 결제는 **가상 승인**입니다. 실제 카드번호를 넣어도 돈이 빠져나가지 않습니다.
   - 테스트로 발급되는 가상계좌는 번호 앞에 X가 붙는 가짜 계좌라 실제 입금이 안 됩니다.
   - 각 API는 분당 100건 요청 제한이 있습니다(2026-07 기준). 반복 실습에는 넉넉한 양입니다.
   - 정산(결제금이 사업자 계좌로 입금되는 것) 기록은 라이브 환경 전용이라 테스트 키로는 볼 수 없습니다. 이 부분은 학습 범위 밖으로 둡니다.

**[✅ 이게 보이면 성공]** 개발자센터에서 test_로 시작하는 클라이언트 키·시크릿 키 두 개를 확인했고, 테스트 결제 후 API 로그 화면에 기록이 남습니다.

**[막히면]** 카카오페이 결제 테스트가 안 됨 → 정상입니다. 카카오페이는 계약 후 발급되는 전용 테스트 키로만 가능하니, 학습 단계에서는 카드 결제로 연습하세요.

## 4. v2 SDK로 결제위젯 붙이기

**[무엇을 배우나]** 결제위젯을 내 페이지에 붙이고 테스트 결제를 한 건 성공시킵니다.

**[왜 필요한가]** 카드 입력 화면을 직접 만들면 보안 규정까지 떠안게 됩니다. 위젯을 쓰면 UI와 보안을 PG가 책임지고, 나는 "어디에 띄울지"만 정하면 됩니다.

시작 전에 가장 중요한 경고 하나. 토스페이먼츠 SDK(개발에 필요한 도구 모음)는 **v1에서 v2로 세대교체**되었습니다. 2023~24년에 쓰인 한국어 튜토리얼 다수는 v1 기준이라 함수 이름부터 다릅니다. 공식 React 블로그 글([React로 결제 페이지 개발하기](https://www.tosspayments.com/blog/articles/paytech-4), 2023)조차 v1입니다. 구분법은 간단합니다.

| | v2 (이걸 쓰세요) | v1 (흐름 참고만) |
|---|---|---|
| 설치 | `@tosspayments/tosspayments-sdk` 또는 스크립트 주소에 `/v2/standard` | `@tosspayments/payment-widget-sdk` |
| 특징 함수 | `widgets()`, `setAmount()` | `loadPaymentWidget()`, `updateAmount()` |

**[따라하기]**

1. [결제위젯(주문서형) 연동하기](https://docs.tosspayments.com/guides/v2/payment-widget/integration) 퀵스타트를 엽니다. 상점관리자의 결제 UI 설정 메뉴에서 UI를 만들고 variantKey(내가 만든 결제 UI를 가리키는 식별 코드)를 복사해 둡니다.
2. 코드 흐름은 네 단계입니다: `TossPayments(클라이언트 키)`로 초기화 → `widgets({customerKey})`로 위젯 인스턴스 생성(customerKey는 구매자를 구분하는 임의 문자열) → `setAmount()`로 금액 설정 → `renderPaymentMethods()`로 결제수단 UI를 화면에 그립니다.
3. "구독하기" 버튼에 `requestPayment({orderId, orderName, successUrl, failUrl})`를 연결합니다. 주문번호·주문명과, 성공·실패 시 이동할 페이지 주소를 넘기는 것입니다.
4. 결제 성공 시 successUrl로 이동하며 결제 정보가 함께 전달됩니다. 서버에서 금액이 원래 주문 금액과 같은지 확인한 뒤 시크릿 키로 승인 API를 호출하면 결제 완료입니다. 전체 파라미터는 [SDK v2 레퍼런스](https://docs.tosspayments.com/sdk/v2/js)에서 찾습니다.

**[✅ 이게 보이면 성공]** 내 페이지 안에 카드·간편결제 선택 UI가 뜨고, 테스트 결제 후 successUrl 페이지에 도착하며, 개발자센터 로그에 해당 결제가 보입니다.

**[막히면]**

- 위젯이 안 그려짐 → `setAmount()`로 금액을 설정했는지, 클라이언트 키가 test_로 시작하는 올바른 키인지 확인하세요.
- 문서와 내 코드의 함수 이름이 다름 → v1 자료를 보고 있을 가능성이 큽니다. [v1→v2 마이그레이션 가이드](https://docs.tosspayments.com/guides/v2/get-started/migration-guide)로 대조하세요. Next.js 기반 velog 글([결제위젯 구현하기](https://velog.io/@sanghyeon/토스-페이먼츠-API를-이용한-결제-위젯-구현하기-Feat.-NextJS-TypeScript), 2024)도 화면 구성 아이디어만 참고하고 코드는 공식 v2 문서를 따르세요.

## 5. 구독(자동결제)까지 가는 학습 경로

OTT의 핵심인 "매달 자동 결제"는 [자동결제(빌링) 연동 가이드](https://docs.tosspayments.com/guides/v2/billing/integration)가 정식 경로입니다. 흐름만 미리 그려 봅니다.

1. `requestBillingAuth()`로 카드 등록창을 엽니다 — 고객이 "이 카드로 계속 결제해도 좋다"고 동의하는 단계
2. 성공하면 successUrl로 authKey(빌링키를 받아올 1회용 인증 코드)가 전달됩니다
3. 서버에서 이 authKey로 **빌링키 발급 API**를 호출하고, 발급된 빌링키를 고객 정보와 짝지어 서버에 저장합니다
4. 결제일마다 빌링키로 **승인 API**를 호출해 결제합니다. 단, "매달 1일에 자동 실행"하는 스케줄링은 토스페이먼츠가 제공하지 않아 직접 구현해야 합니다

테스트 환경에서는 본인인증 문자 대신 **인증번호 000000**을 입력하면 되고, 카드번호 앞 여섯 자리만 유효하면 등록되므로 실카드 없이 전체 흐름을 검증할 수 있습니다. 자동결제는 국내 발급 카드만 지원합니다. 실서비스 적용은 별도 계약과 리스크 검토가 필요하므로, 학습 단계에서는 테스트 환경까지가 목표입니다.

솔직히 말해, "결제 포함 OTT 클론"을 처음부터 끝까지 다루는 한국어 단일 자료는 현재 없습니다. 다음 조합이 현실적인 경로입니다.

- **백엔드 로직**: 공식 블로그 [구독 결제 서비스 구현하기 (1)(2)](https://docs.tosspayments.com/blog/subscription-service-1) — 빌링키 발급→DB 관리→스케줄링을 다룹니다. 예제가 Express(오래된 자바스크립트 서버 프레임워크) 기반이니 코드보다 설계를 흡수하세요
- **영문·Stripe 대안**: Vercel 공식 [nextjs/saas-starter](https://github.com/nextjs/saas-starter) 템플릿과 [Stripe + Next.js 15 완전 가이드](https://www.pedroalonso.net/blog/stripe-nextjs-complete-guide-2025/) — PG만 다를 뿐 구독 결제의 구조(체크아웃→웹훅→구독 관리)는 동일합니다

## 6. AI에게 시키기 — 토스페이먼츠 공식 MCP

토스페이먼츠는 PG 최초로 공식 MCP(AI가 다른 프로그램과 대화하는 표준 연결 규격) 서버를 제공합니다. Cursor에 붙이면 AI가 결제 연동 문서를 직접 검색하면서 코드를 짜 주므로, 이 프로젝트와 궁합이 좋습니다.

1. [AI 도구로 결제 연동하기](https://docs.tosspayments.com/guides/v2/get-started/llms-guide) 문서를 엽니다. Cursor는 딥링크(클릭 한 번으로 설치되는 링크)를 지원하고, 수동 설치라면 mcp.json에 `npx -y @tosspayments/integration-guide-mcp@latest` 실행 설정을 넣습니다.
2. Cursor 채팅에 이렇게 요청합니다: "토스페이먼츠 결제위젯을 주문서형으로 연동해 줘. **v2 SDK 기준으로.**" — MCP는 버전을 지정하지 않으면 v2 문서를 검색하지만, 명시하면 AI가 옛 학습 데이터의 v1 코드를 섞을 여지가 줄어듭니다.
3. 함께 쓰면 좋은 재료: 결제 연동 핵심을 압축한 [LLM Quick Reference](https://docs.tosspayments.com/guides/v2/get-started/llms-quick-reference), 문서 전체 목차인 [llms.txt](https://docs.tosspayments.com/llms.txt), 그리고 모든 공식 문서 URL 끝에 `.md`를 붙이면 AI에게 그대로 먹일 수 있는 마크다운 원문이 나온다는 팁입니다.
