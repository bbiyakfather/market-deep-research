# 결제 연동하기

AI에게 질문

결제위젯 SDK v1은 더 이상 업데이트되지 않습니다. [토스페이먼츠 SDK v2](https://docs.tosspayments.com/guides/v2/payment-widget/integration) 연동을 추천합니다.

모든 결제수단을 한 번에 연동할 수 있는 샘플 프로젝트입니다. 프로젝트 언어를 선택하고 빠르게 시작하세요. 연동이 끝나면 노코드로 결제수단 설정과 디자인을 변경할 수 있어요.

아래 **문서용 테스트 키** 또는 **전자결제 신청 이후에 확인 가능한 결제위젯 연동 키**를 사용하세요.

```
test_gck_docs_Ovk5rk1EwkEbP0W43n07xlzm
test_gsk_docs_OaPz8L5KdmQXkzRz3y47BMw6
```

[결제위젯 렌더하기](https://docs.tosspayments.com/guides/payment-widget/integration#%EA%B2%B0%EC%A0%9C%EC%9C%84%EC%A0%AF-%EB%A0%8C%EB%8D%94%ED%95%98%EA%B8%B0)

Client

SDK 설치

스크립트 태그 또는 npm 패키지로 결제위젯 SDK를 설치하세요.

`<script src="https://js.tosspayments.com/v1/payment-widget">`

`npm install @tosspayments/payment-widget-sdk`

결제위젯 초기화

클라이언트 키, `customerKey`로 결제위젯 SDK를 초기화하세요.

클라이언트 키를 불러오세요.

개발자센터에서 [결제위젯 연동 키 > 클라이언트 키](https://developers.tosspayments.com/my/api-keys)를 불러오세요. 결제위젯 연동 키는 토스페이먼츠 전자결제 신청 이후에만 확인할 수 있어요. 신청 전에는 아래 테스트 키로 연동해보세요.

`test_gck_docs_Ovk5rk1EwkEbP0W43n07xlzm`

customerKey를 설정하세요.

회원 구매자의 `customerKey`를 불러오는 로직을 추가하세요. 비회원 구매자는 `ANONYMOUS` 값으로 결제위젯을 초기화할 수 있어요.

`customerKey`는 구매자와 1:1 관계로 연결되는 값입니다. [UUID](https://docs.tosspayments.com/resources/glossary/uuid)와 같이 충분히 무작위적인 고유 값을 사용하세요. 다른 사용자가 이 값을 알게 되면 악의적으로 사용될 수 있습니다. 자동 증가하는 숫자 또는 이메일・전화번호・사용자 아이디와 같이 유추가 가능한 값은 안전하지 않습니다.

결제 영역 정의

결제 UI, 이용약관 UI를 보여주고 싶은 영역을 각각 `div` 태그로 정의하세요. 결제 버튼도 만들어주세요.

결제 UI 렌더링

DOM이 생성된 이후에 [`renderPaymentMethods()`](https://docs.tosspayments.com/sdk/widget-js#renderpaymentmethods%EC%84%A0%ED%83%9D%EC%9E%90-%EA%B2%B0%EC%A0%9C-%EA%B8%88%EC%95%A1-%EC%98%B5%EC%85%98) 메서드로 결제 UI를 렌더링하세요. 결제 영역의 `div` CSS 선택자(Selector)와 결제 금액을 파라미터로 넣으세요. 여러 결제 UI를 만들었다면, `variantKey`를 결제위젯 어드민에서 확인하고 파라미터로 넘기세요.

variantKey는 뭔가요?

어드민에서 결제 UI를 여러 개 만들었다면, 각 UI에 부여되는 키에요. 더 자세한 내용은 [새로운 결제 UI 추가하기](https://docs.tosspayments.com/guides/payment-widget/admin#%EC%83%88%EB%A1%9C%EC%9A%B4-%EA%B2%B0%EC%A0%9C-ui-%EC%B6%94%EA%B0%80%ED%95%98%EA%B8%B0)를 참고하세요.

렌더링이 완료되었을 때 이벤트를 받을 수 있나요?

네. [`ready`](https://docs.tosspayments.com/sdk/widget-js#on%EC%9D%B4%EB%B2%A4%ED%8A%B8-%EC%BD%9C%EB%B0%B1) 이벤트로 결제 UI 렌더링 완료 이벤트를 받을 수 있습니다.

```
const paymentMethodWidget = paymentWidget.renderPaymentMethods(
  "#payment-method",
  { value: 50000 },
  { variantKey: "DEFAULT" }
);

paymentMethods.on('ready', () => {
  // 결제 버튼 활성화
})
```

애플페이가 왜 안 보이나요?

애플페이는 iPhone 및 Mac Safari 에서만 노출돼요. 어드민 페이지에서는 예상 이미지를 확인할 수 있습니다.

결제 UI가 렌더링되지 않아요.

*   `UNAUTHORIZED_KEY` 에러가 나면 클라이언트 키를 다시 확인하세요.
*   `NOT_REGISTERED_PAYMENT_WIDGET` 에러가 나면 상점관리자에서 결제 UI를 추가하세요. 결제 UI가 생성되지 않았을 때 발생하는 에러입니다.
*   CSS 선택자(Selector)를 정확히 입력했는지 확인하세요.
*   특정 브라우저 환경에서만 렌더링이 안 된다면 익스텐션을 확인하세요. [IE 환경](https://docs.tosspayments.com/guides/environment#%EC%A7%80%EC%9B%90-%ED%94%8C%EB%9E%AB%ED%8F%BC%EB%B8%8C%EB%9D%BC%EC%9A%B0%EC%A0%80-%ED%99%98%EA%B2%BD)은 지원하지 않습니다.

이용약관 UI 렌더링

`renderAgreement()` 메서드로 이용약관 UI를 렌더링하세요. 이용약관 영역의 `div` CSS 선택자(Selector)를 파라미터로 넣으세요.

(선택) 기타 결제 UI 추가

할인 쿠폰, 가격 정보 등 구매자에게 보여주고 싶은 기타 결제 UI를 직접 만들어서 추가해주세요.

(선택) 결제 금액 업데이트

결제 금액을 업데이트하려면 [`updateAmount()`](https://docs.tosspayments.com/sdk/widget-js#updateamount%EA%B2%B0%EC%A0%9C-%EA%B8%88%EC%95%A1)를 호출하세요. 파라미터에 새로운 결제 금액을 넣어주세요. 예를 들어, 5만원 주문에 5천원이 할인됐다면 4만5천원을 넣어주세요.

* 결제 금액이 UI에서 바뀌는 시점에 해당 메서드를 호출하세요.

[결제 요청하기](https://docs.tosspayments.com/guides/payment-widget/integration#%EA%B2%B0%EC%A0%9C-%EC%9A%94%EC%B2%AD%ED%95%98%EA%B8%B0)

Client

결제 버튼 이벤트 설정

결제를 요청하기 전에 `orderId`와 `amount`를 서버에 임시로 저장하세요. 결제 요청과 승인 사이에 데이터 무결성을 확인할 때 필요해요. 더 자세한 내용은 [결제 흐름](https://docs.tosspayments.com/guides/learn/payment-flow#%EA%B2%B0%EC%A0%9C-%EC%9A%94%EC%B2%AD-%EC%A0%84%EC%97%90-%EA%B2%B0%EC%A0%9C%ED%95%A0-%EB%8D%B0%EC%9D%B4%ED%84%B0-%EC%A0%80%EC%9E%A5%ED%95%98%EA%B8%B0) 가이드에서 확인하세요.

결제 버튼에 결제 요청 메서드 [`requestPayment()`](https://docs.tosspayments.com/sdk/widget-js#requestpayment%EA%B2%B0%EC%A0%9C-%EC%A0%95%EB%B3%B4)를 이벤트로 걸어주세요. 더 많은 파라미터는 [SDK 문서](https://docs.tosspayments.com/sdk/widget-js#requestpayment-%ED%8C%8C%EB%9D%BC%EB%AF%B8%ED%84%B0)에서 확인하세요.

결제 UI가 렌더링된 이후에 결제 요청 메서드를 호출하세요. [`ready`](https://docs.tosspayments.com/sdk/widget-js#on%EC%9D%B4%EB%B2%A4%ED%8A%B8-%EC%BD%9C%EB%B0%B1) 이벤트로 결제 UI 렌더링 완료 이벤트를 받을 수 있습니다.

결제 UI가 렌더링되기 전에 결제를 요청하면 어떻게 되나요?

구매자가 선택한 결제수단의 결제창이 정상적으로 열리지 않습니다. 반드시 결제 UI가 렌더링된 이후에 결제 요청 메서드를 호출하세요.

구매자가 선택한 결제수단을 미리 알 수 있나요?

네. 결제를 요청하기 전에 [`getSelectedPaymentMethod()`](https://docs.tosspayments.com/sdk/widget-js#getselectedpaymentmethod)를 호출해서 구매자가 선택한 결제수단을 확인할 수 있습니다.

커스텀 파라미터를 보내고 승인 응답으로 받고 싶어요.

결제 성공 후 이동하는 `successUrl`로 받으세요. 적은 양의 데이터라면 `successUrl`의 [쿼리 파라미터](https://docs.tosspayments.com/resources/glossary/query-param)로 추가하세요.

만약 데이터가 많거나 결제 완료 전에 데이터를 처리해야 한다면, 결제 요청을 하기 전에 데이터베이스에 저장하세요.

결제창 띄우기

결제 UI에서 자주 사용하는 결제수단을 선택하고 '결제하기' 버튼을 누르세요. 선택한 결제수단의 결제창에서 정보를 입력하세요. 테스트 환경에서는 결제가 가상으로만 이뤄지기 때문에 결제수단에서 금액이 차감되지 않아요. 결제를 마치면 결제 인증이 완료된 거예요.

클라이언트는 결제 인증이 성공하면 `successUrl`로 이동하고, 실패하면 `failUrl`로 이동해요.

계속 로딩 중인 화면에서 변화가 없어요.

아직 결제 요청 중이에요. 이어서 `successUrl`, `failUrl` 페이지에서 요청 결과를 확인한 뒤, 결제 승인 API까지 호출해야 결제가 완료돼요. iframe을 사용하고 있다면 요청 결과 페이지(`successUrl`, `failUrl`)로 이동할 수가 없어요.

모바일 환경에서 화면이 카드사로 이동하지 않아요.

카드사 앱스킴을 등록해야 돼요. 자세한 내용은 [웹뷰 가이드](https://docs.tosspayments.com/guides/webview)에서 확인하세요.

iframe에서 결제창을 띄울 수 있나요?

iframe을 이용한 결제창 팝업 형태는 PC에서만 제공하고 있습니다.

왜 페이지가 이동하나요?

결제 인증과 승인 사이에는 클라이언트가 이동하는 리다이렉트 과정이 있습니다.

**결제 요청 과정에서 인증 결과를 받고 다음 단계로 넘어가기 위해 [리다이렉트 URL 확인과 처리](https://docs.tosspayments.com/sdk/widget-js#%EB%A6%AC%EB%8B%A4%EC%9D%B4%EB%A0%89%ED%8A%B8-url%EB%A1%9C-%EC%B2%98%EB%A6%AC%ED%95%98%EA%B8%B0)가 필요합니다.** 토스페이먼츠에서 인증 결과를 URL의 [쿼리 파라미터](https://docs.tosspayments.com/resources/glossary/query-param)에 담아 리다이렉트하면, 상점에서는 리다이렉트 URL을 받아 결제를 승인할 수 있어요.

더 자세한 내용은 [리다이렉트 처리하기](https://docs.tosspayments.com/guides/learn/redirect), [결제 흐름 이해하기](https://docs.tosspayments.com/guides/learn/payment-flow)에서 확인해보세요.

3

[리다이렉트 URL로 이동하기](https://docs.tosspayments.com/guides/payment-widget/integration#%EB%A6%AC%EB%8B%A4%EC%9D%B4%EB%A0%89%ED%8A%B8-url%EB%A1%9C-%EC%9D%B4%EB%8F%99%ED%95%98%EA%B8%B0)

Client

successUrl로 이동한 경우

결제 요청이 성공하면 `successUrl`로 이동합니다. URL에 아래 [네 가지 쿼리 파라미터](https://docs.tosspayments.com/sdk/widget-js#%EC%84%B1%EA%B3%B5-%EC%9D%91%EB%8B%B5)가 추가돼요.

```
/success?paymentType={PAYMENT_TYPE}&orderId={ORDER_ID}
&paymentKey={PAYMENT_KEY}&amount={AMOUNT}
```

쿼리 파라미터의 `amount` 값과 `renderPaymentMethods()`의 `amount` 파라미터의 값이 같은지 반드시 확인하세요. 클라이언트에서 결제 금액을 조작하는 행위를 방지할 수 있습니다. 만약 값이 다르다면 결제를 취소하고 구매자에게 알려주세요.

서버로 결제정보 전달

서버로 `paymentKey`, `amount`, `orderId` 값을 전달하세요. 결제 승인에 필요한 데이터입니다. 결제 승인 결과에 따라 클라이언트에서 필요한 결제 성공 및 실패 로직을 추가하세요.

failUrl로 이동한 경우

결제 요청이 실패하면 `failUrl`로 이동합니다. 쿼리 파라미터로 돌아오는 에러 코드, 메시지를 확인하고 필요한 로직을 구현해주세요.

```
/fail?code={ERROR_CODE}&message={ERROR_MESSAGE}
&orderId={ORDER_ID}
```

트러블슈팅 PAY_PROCESS_CANCELED

**오류원인**

구매자에 의해 결제가 취소되면 `PAY_PROCESS_CANCELED` 에러가 발생합니다. 결제 과정이 중단된 것이라서 `failUrl`로 `orderId`가 전달되지 않아요.

트러블슈팅 PAY_PROCESS_ABORTED

**오류원인**

결제가 실패하면 `PAY_PROCESS_ABORTED` 에러가 발생합니다.

**해결 방법**

*   오류 메시지를 확인하세요. 계약 관련 오류는 토스페이먼츠 고객센터(1544-7772, [support@tosspayments.com](mailto:support@tosspayments.com))로 문의해주세요.

*   기타 오류는 토스페이먼츠 [실시간 기술지원 채널](https://discord.com/invite/A4fRFXQhRu)에서 문의해주세요.

트러블슈팅 REJECT_CARD_COMPANY

**오류원인**

구매자가 입력한 카드 정보에 문제가 있다면 `REJECT_CARD_COMPANY` 에러가 발생합니다.

**해결 방법**

*   오류 메시지를 확인하고 구매자에게 안내를 해주세요.

시크릿 키로 Basic 인증 헤더 설정

개발자센터에서 [결제위젯 연동 키 > 시크릿 키](https://developers.tosspayments.com/my/api-keys)를 불러오세요. 결제위젯 연동 키는 토스페이먼츠 전자결제 신청 이후에만 확인할 수 있어요. 신청 전에는 아래 테스트 키로 연동해보세요.

`test_gsk_docs_OaPz8L5KdmQXkzRz3y47BMw6`

시크릿 키와 `:`을 [base64](https://docs.tosspayments.com/resources/glossary/base64)로 인코딩해서 [Basic 인증 헤더](https://docs.tosspayments.com/reference/using-api/authorization#%EC%8B%9C%ED%81%AC%EB%A6%BF-%ED%82%A4%EB%A1%9C-%EC%9D%B8%EC%A6%9D%ED%95%98%EA%B8%B0)를 아래와 같이 만들어주세요. `:`을 빠트리지 않도록 주의하세요. 비밀번호가 없다는 것을 알리기 위해 시크릿 키 뒤에 콜론을 추가합니다.

`Basic base64("{WIDGET_SECRET_KEY}:")`

* 시크릿 키는 클라이언트, GitHub 등 외부에 노출되면 안 됩니다.

결제 승인 API 호출

결제를 승인하면 결제수단에서 금액이 차감돼요. 토스페이먼츠 [결제 승인 API](https://docs.tosspayments.com/reference#%EA%B2%B0%EC%A0%9C-%EC%8A%B9%EC%9D%B8)를 호출해서 결제를 완료하세요.

Authorization 헤더에 인코딩된 시크릿 키값을 추가하세요. `orderId`, `amount`, `paymentKey`를 요청 데이터로 사용하세요.

5

[결제 승인 결과 확인하기](https://docs.tosspayments.com/guides/payment-widget/integration#%EA%B2%B0%EC%A0%9C-%EC%8A%B9%EC%9D%B8-%EA%B2%B0%EA%B3%BC-%ED%99%95%EC%9D%B8%ED%95%98%EA%B8%B0)

Server

성공 응답

결제 승인에 성공하면 HTTP `200 OK`와 [Payment 객체](https://docs.tosspayments.com/reference#payment-%EA%B0%9D%EC%B2%B4)를 받습니다.

**데이터 저장**

`paymentKey`, `orderId`는 서버에 필수로 저장하세요. 결제 조회, 결제 취소에 사용되는 값입니다. 나머지 값들은 필요에 따라 저장하세요.

**결제수단**

응답 객체에 선택한 결제수단 정보를 확인하세요. 결제 UI에서 신용・체크를 선택했다면, `card` 필드에 카드 정보 객체가 돌아와요. `method` 필드도 `카드`로 나와요.

*   간편결제는 [간편결제 응답 가이드](https://docs.tosspayments.com/guides/learn/easypay-response)를 확인하세요.

*   가상계좌는 [테스트 결제내역](https://developers.tosspayments.com/my/payment-logs)에서 입금을 처리할 수 있어요. 가상계좌는 반드시 [웹훅을 연동](https://docs.tosspayments.com/blog/virtual-account-webhook)해야 최종 입금 알림을 받을 수 있어요.

**API 버전**

응답 객체는 API 버전에 따라 조금씩 달라집니다. [개발자센터](https://developers.tosspayments.com/my/api-keys)에 설정된 API 버전을 확인하고, 원하는 필드가 있는 버전으로 변경해보세요. API 버전 업데이트 사항은 [릴리즈 노트](https://docs.tosspayments.com/resources/release-note)에서 확인할 수 있습니다.

실패 응답

결제 승인에 실패하면 HTTP `4XX` 또는 `5XX` 코드와 에러 객체를 받습니다. 결제 승인의 전체 오류 목록은 [에러 코드](https://docs.tosspayments.com/reference/error-codes#%EA%B2%B0%EC%A0%9C-%EC%8A%B9%EC%9D%B8)를 참고하세요.

```
{
  "code": "NOT_FOUND_PAYMENT_SESSION",
  "message": "결제 시간이 만료되어 결제 진행 데이터가 존재하지 않습니다."
}
```

트러블슈팅 NOT_FOUND_PAYMENT_SESSION

**오류원인**

결제 승인에서 요청에 문제가 있으면 `NOT_FOUND_PAYMENT_SESSION` 에러가 발생합니다.

**해결 방법**

*   결제 요청이 완료된 이후 10분 이내에 결제를 승인해야 됩니다. 10분이 지나면 결제 데이터가 유실되어 승인이 불가합니다.

*   결제 요청했을 때 돌려받은 `paymentKey`와 결제 승인에 사용한 `paymentKey`가 같은 값인지 확인하세요.

*   결제 요청에 사용한 클라이언트 키와 결제 승인에 사용한 시크릿 키가 매칭된 키값인지 확인하세요.

트러블슈팅 REJECT_CARD_COMPANY

**오류원인**

카드사에서 해당 카드를 거절했을 때 `REJECT_CARD_COMPANY` 에러가 발생합니다. 원인은 비밀번호 오류, 한도 초과, 포인트 부족 등 다양합니다.

**해결 방법**

에러 메시지를 확인해서 원인을 파악하고 구매자에게 올바른 안내를 해주세요.

트러블슈팅 FORBIDDEN_REQUEST

**오류원인**

API 키값 또는 주문번호가 최초 요청한 값과 다르면 `FORBIDDEN_REQUEST`가 발생합니다.

**해결 방법**

*   결제 요청에 사용한 클라이언트 키와 API 호출에 사용한 시크릿 키가 매칭된 키값인지 확인하세요.

*   `orderId`, `paymentKey` 값이 최초 결제 요청한 값과 같은지 확인하세요.

트러블슈팅 UNAUTHORIZED_KEY

**오류원인**

API 키를 잘못 입력하면 `UNAUTHORIZED_KEY` 에러가 발생합니다.

**해결 방법**

*   클라이언트 키와 매칭된 시크릿 키를 사용하고 있는지 확인하세요. API 키는 토스페이먼츠에 로그인한 뒤에 개발자센터의 [API 키 메뉴](https://developers.tosspayments.com/my/api-keys)에서 확인할 수 있어요.

*   [시크릿 키 인코딩](https://docs.tosspayments.com/reference/using-api/authorization#%EC%8B%9C%ED%81%AC%EB%A6%BF-%ED%82%A4%EB%A1%9C-%EC%9D%B8%EC%A6%9D%ED%95%98%EA%B8%B0)을 다시 확인하세요. 시크릿 키 뒤에 `:`을 추가하고 base64로 인코딩해서 사용해야 됩니다.

다음 단계

결제 연동을 완성하셨어요. 이제 개발자센터에서 [테스트 결제내역](https://developers.tosspayments.com/my/payment-logs)을 확인하거나 [토스페이먼츠 코어 API](https://docs.tosspayments.com/reference)로 결제를 조회 또는 취소해보세요.

실시간으로 결제 알림을 받고 싶다면 [웹훅을 연동하세요](https://docs.tosspayments.com/guides/webhook).
