# research-plan — 조사계획 확정 게이트 (G0 선행, 산출물: `audit/research-plan.md`)

축(조사질문=에이전트 분할=3부 챕터의 단일 개념, `references/report-format.md` 축 프리셋 참조)은
조사가 시작되기 전에 확정돼야 한다. 확정 없이 조사원을 팬아웃하면 축이 조사 도중 흔들려
"3부 챕터를 못 채우는 축"·"에이전트가 없는 축" 불일치가 재발한다. 이 문서는 확정 필드·절차·
축 도출 체인·품질 기준·승인 목차 서식을 정의하는 G0 선행 게이트다(`entity-identity.md` 와
같은 격식 — 그 문서가 기관·기업 조사의 "대상"을 확정한다면, 이 문서는 모든 조사유형의
"질문·범위·종료조건"을 확정한다).

**§0 독자·목표가 선행한다.** 아래 필드보다 먼저 `references/reader-goal.md` 의 독자·목표 필드(의뢰인·1차
독자·설득 대상·독자의 결정·**핵심 메시지 가설**·관점·입력 자료 지위·제외·독자 테스트 질문)를 사용자와
확정해 `audit/research-plan.md` 맨 앞에 `## §0 독자·목표` 헤딩 + 표로 적는다(`# 부`·`## 축:`·'부록' 시작 헤딩 금지 —
목차 파서가 승인 부·부록 경계로 읽는다. §0 은 승인 시점에 동결, 교체 메시지는 `intent-diff.md` `현행 메시지:` 줄).
'의사결정 용도'는 §0 의 '독자의 결정'을 그대로 받고,
`audit/intent-diff.md` 는 핵심 메시지 가설을 축별로 분해해 개시한다. §0 없이 축을 세우면 조사가 끝난 뒤
독자·관점을 재정의해 전면 재집필하게 된다(2026-10 세 프로젝트 실측).

## 확정 필드 (승인 전 전부 채움)
| 필드 | 내용 | 미확정 시 위험 |
|---|---|---|
| 의사결정 용도 | 고객이 이 보고서로 무엇을 정하는가(투자·진입·제휴·정책대응 등) | 조사 깊이·축 우선순위가 근거 없이 팀리드 임의 판단이 됨 |
| 시장/기술 정의 | 무엇을 이 시장/기술로 세는가, 인접 영역 포함 여부 | 인접 시장 수치가 섞여 claim_key 가 오염(다른 정의의 수치를 같은 것으로 합산) |
| 세분화 축 | 제품/지역/용도 등 어떤 축으로 시장을 쪼개 보는가 | 보고서 전반의 수치 단위가 조사원마다 달라 합산·비교 불가 |
| 조사 대상 기간 | 과거 몇 년 + 전망 몇 년 | 조사원마다 다른 기간의 수치를 같은 claim_key 로 등재해 값불일치로 오판정 |
| 지역 범위 | 글로벌/권역/국가 단위 | 지역 미표기 수치가 섞여 규모 착시(글로벌 수치를 국내로 오인) |
| 언어 범위 | 조사에 포함할 원문 언어 | 특정 언어권 소스 누락을 "결과 없음"으로 오판정(축 결론 조기 확정) |
| 조사질문 축 3~5개 | 이 조사가 답해야 할 질문 목록(품질 기준은 아래) | 축 없이 팬아웃하면 에이전트 분할·3부 챕터 구조가 매 조사마다 달라짐 |
| out-of-scope | 이번 조사에서 다루지 않는 것(인접 주제·제외 지역·제외 기간) | 범위 경계가 없으면 확장수렴 루프가 무한 팬아웃(깊이캡 도달까지 무분별 확장) |
| 축별 충분조건 | 축마다 "이 정도면 충분"의 구체 기준(1차출처 확보·N건 교차확인 등) | 축마다 종료 판단이 팀리드 감(感)이 되어 조사마다 깊이가 달라짐 |
| 루프 수렴조건 | 확장수렴 루프 자체의 종료조건(SKILL.md 의 "루프 수렴조건"과 동일 개념 참조) | 축별 충분조건과 혼동되면 리드 0인데도 루프가 안 멈추거나 반대로 조기 종료 |
| 깊이캡 기본값(숫자) | 최대 확장 웨이브 수·최대 스폰 에이전트 수(기본 3회/12명 — BM·사업화 조사 실측 3건은 5~6웨이브/30~40명으로 끝났으니 같은 유형이면 초안에 그 수준을 제안) | 상한이 없으면 확장수렴 루프가 예산·시간 한계 없이 팬아웃 |
| 승인 목차 | 아래 "승인 목차 예시" 서식으로 부·축 확정(서식은 고정, 내용은 조사별) | 목차 없이 시작하면 G9 목차 기계검사가 무엇을 기준으로 대조할지 없음 |
| 인용·기밀 제약 | 고객 재배포 가능 여부·NDA 소스 인용 제한 | 부록 소스 목록에 재배포 불가 자료가 노출돼 고객 배포 사고 |
| 선행 문서 기준선 | 전년판·기존 양식·상사 초안이 있으면 **전문 선열람** 후 기준선 표(결론·수치·구조)를 뽑고, 기존 기재값 처리(재사용/전량 폐기)를 정한다. 폐기 수치·금지 서술은 목록으로 두고 [3] 뒤 원고 전체 grep 0건(폐기한 옛 양식 주장이 워커 산출물로 되돌아온 사례) | 전년판 결론을 복사해 취소된 프로젝트를 '성공 모델'로 서술(PEM 2026) · 양식 수치 110건 중 근거 확인 10건(출연연 BM) |
| 의뢰인 확인 채널 | 조사로 닫을 수 없는 항목(연구팀 스펙·확정 마커·공개 범위)을 누가 언제 답하나. 불가 시 처리 원칙('미확정'·`[상충]` 병기) | 경쟁사 6항목 데이터시트를 전부 확보하고도 우리 칸만 전부 '미확인'(출연연 BM) |
| high-risk 범위·독립성 요건 | 기본 = 시장규모·성장률·딜규모·순위 는 `risk:high`, 독립 관찰그룹 2 필수(verify_facts 에 예외 장치 없음 — high 인데 1그룹이면 v4 G3 FAIL). 사용자가 완화하면 = 해당 사실을 `risk:normal` 로 등재하되 COUNTER 반박검색 1회는 유지, 본문에 "<집계 주체> 단일 출처" 표기, 이 표에 변경 기록 | 기록 없이 완화하면 [Bx] 반박검색이 조용히 무력화(촉매 저감 조사 high 0건) |
| 납품 형식 | 증빙판 PDF 만 / hwpx 양식(표지 원본·목차 규칙·쪽번호·요약 위치·참고문헌 유무, 기본 PEM 2026년판) / PPTX 양식. 조사용 코드(T1·W3·G0)의 납품본 명칭도 여기서 함께 정한다 | 표지·목차를 끝에서 두 번 재작업, 내부 코드 사후 치환 130건(촉매 저감 조사) |

무신규 웨이브는 `join_workers.py` verdict가 **ok인 워커의 EXPAND 기준**으로만 판정한다. blocked/invalid 워커는 무신규 관측으로 세지 않는다.

## 확정 절차 (팬아웃 금지 — 승인 전 조사원 스폰 금지)
1. 팀리드가 §0 독자·목표와 위 확정 필드 전부를 초안 작성(주제·요청 맥락에서 추론 가능한 만큼 채움).
2. **사용자 승인**: 초안(특히 축 3~5개·out-of-scope·승인 목차)을 사용자에게 확인받는다.
   승인 전에는 병렬 조사원을 팬아웃하지 않는다(요청 오독으로 인한 팬아웃 낭비 차단).
3. 승인된 내용을 `audit/research-plan.md` 에 확정 기록(G0 산출물). 이후 모든 조사원 TASK·
   3부 챕터 구조는 이 파일의 축 목록을 그대로 따른다(임의 추가·누락 금지).
4. 확정 후 [1] 병렬 조사 착수. SKILL.md 파이프라인 반영(요구사항 확정 절차·G0 산출물 참조)은
   별도 배치에서 진행(현재 이 문서는 선행 정의만 — SKILL.md 본문 수정은 이번 배치 범위 밖).

## 축 도출 체인 (1:1 대응 강제)
```
독자·목표(핵심 메시지 가설) → 의사결정 용도 → 조사질문 → 축 → 에이전트 배정 → 3부 챕터
```
체인의 각 화살표는 1:1이다 — 조사질문 하나가 축 하나를 낳고, 축 하나가 에이전트 분할 단위
하나(또는 그 배수)가 되며, 그 축 이름이 그대로 3부의 챕터 소제목이 된다. 축 이름이 이 체인
바깥에서 새로 지어지면(예: 챕터만 있고 대응하는 조사질문이 없으면) 그 챕터는 채워지지 않는다.
축 프리셋(조사유형별 기본 축 목록)은 `references/report-format.md` 의 "조사유형별 목차 변형"
절이 유일한 진실원이다 — 이 문서는 그 프리셋을 어떻게 골라 쓰는지(도출 체인·품질 기준)만
규정하고, 축 이름 자체를 다시 나열하지 않는다.

## 축 품질 기준
- **MECE**: 축끼리 겹치지 않고(Mutually Exclusive), 합쳐서 조사질문 전체를 덮는다(Collectively
  Exhaustive). 겹치면 같은 수치가 두 축의 조사원에게 중복 수집돼 claim_key 충돌이 난다.
- **사실·수치로 종결 가능한 질문 형태**: 축은 서술형 주제가 아니라 답이 나오면 끝나는 질문이어야
  한다. "시장은 어떤가" ✗(끝없이 확장됨) → "2024년 글로벌 설치용량과 상위 5개국 비중은" ○
  (수치 확보로 종결 판단 가능).
- **축 3~5개**: 3개 미만이면 조사질문이 뭉뚱그려져 챕터가 과부하되고, 5개 초과면 에이전트
  분할이 과세분화돼 교차검증 비용만 늘어난다.
- **축별 "무너지는 결론" 한 줄**: 각 축에 "이 축이 답을 못 내면 어느 결론이 무너지는가"를
  한 줄 붙인다. 답을 못 내도 보고서 결론에 영향이 없는 축은 애초에 축이 아니라 참고정보다.

## 승인 목차 예시 (기계 파싱 대상 — G9 `--plan` 옵션이 이 서식을 정규식으로 읽는다)
부 번호·제목은 `# 부 N. 제목`, 3부 하위 축 챕터는 `## 축: 이름` 으로 고정 표기한다(정규식
`^# 부 (\d+)\.\s*(.+)$` / `^## 축:\s*(.+)$` 로 추출 가능해야 하므로 서식을 임의 변경하지 않는다).
예시(기술동향 유형, 축은 조사별로 승인된 값으로 교체):
```
# 부 0. 표지·메타
# 부 1. Executive Summary
# 부 2. 조사 개요
# 부 3. 테마별 본론
## 축: 기술요소
## 축: 플레이어
## 축: 시장
## 축: 정책
# 부 4. 시장 수치 종합
# 부 5. 연구기관 매핑
# 부 6. 검증 요약
# 부 7. 상충·모순
# 부 8. 상태 변화·주의
# 부 9. 한계와 반론
# 부 10. 한눈 요약표 + 조사팀 인사이트
# 부 11. 부록
```
11부 표준목차 골격(`report-format.md`) 자체는 조사유형과 무관하게 고정 — 승인 목차에서 바뀌는
것은 3부의 `## 축:` 목록뿐이다(유형별 축 프리셋은 `report-format.md` 참조).
