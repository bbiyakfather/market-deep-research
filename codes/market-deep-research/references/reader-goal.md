# reader-goal — 독자·목표 설계 (G0 최선행, 산출물: `audit/research-plan.md` §0)

조사의 축·깊이·문체보다 먼저 정하는 것은 **누가 이 문서를 들고 누구를 설득해 무엇을 결정하는가**다.
이것이 비어 있으면 사실 검증이 완벽해도 "내용에 코어가 없음"(2026-10-06 촉매 저감 조사 납품본 사용자 판정)이 된다 —
촉매 저감 조사(창업팀 접근 본문 0회 → v3 재구성)·체외진단 용역(관점·성격 미확정 → v13~v15 재집필)·출연연 BM(전제 반증 → 논지 교체)
셋 다 G0 에서 아래 필드를 채웠으면 한 번에 잡혔다.
§0 서식: `audit/research-plan.md` 맨 앞에 `## §0 독자·목표` 헤딩 + 아래 표. `# 부`·`## 축:`·'부록'으로 시작하는
헤딩은 넣지 않는다(목차 파서가 승인 부·부록 경계로 읽어 G3 FAIL). §0 은 승인 시점 가설로 **동결**된다(G0 해시 결박).

## 확정 필드 (research-plan 확정 필드보다 먼저 채우고 사용자 승인)
| 필드 | 묻는 것 | 예 — 기술이전을 원하는 연구자의 BM 보고서 |
|---|---|---|
| 의뢰인 | 누가 발주·대금을 내는가 | 출연연 기술사업화 부서(연구자 지원 과업) |
| 1차 독자 | 누가 실제로 읽고 쓰는가 | 연구자 본인 |
| 설득 대상(2차 독자) | 1차 독자가 이 문서를 들고 설득할 상대. 정해진 기업인가, 후보군 발굴부터인가(→ 5부 수요기업 매핑 범위). 없으면 "본인 판단" | 기술이전을 검토하는 기업의 사업개발 담당 — 후보군 발굴부터 |
| 독자의 결정·행동 | 이 문서를 읽고 무엇을 정하는가 | 기업: 기술이전 검토 착수 여부 / 연구자: 어느 기업·어느 응용부터 제안할지 |
| 핵심 메시지 가설 | 한 문장, "A 는 B 에서 C 때문에 D" 꼴. 조사가 입증 또는 기각할 명제. 근거 강도를 넘지 않는다(실증 전이면 '제거'가 아니라 '연장') | "이 EH-PMIC 는 병원 자산추적 태그의 배터리 교체 주기를 늘려 유지비를 줄이므로 태그 제조사에 유망하다" |
| 보고서 관점(주어·말투) | 누구 입장에서 쓰나. 입력 자료를 평가하는 말투 허용 여부 | 연구자 입장이되 기업의 질문(도입 비용·인증 부담·공급 형태)에 답하는 구성 |
| 우리 기술 근거 | 성능·TRL·특허(등록/출원·공동소유)를 공개 원문(논문·특허 명세서)으로 댈지, 연구자 제공값은 "연구팀 제시값"으로 따로 표기할지, 기업 공개 범위(NDA 전/후 판본) — 증빙 모델은 공개 원문만 받으므로 미리 정한다 | 특허·TRL 은 공개 원문, 미공개 효율은 NDA 판본에만 '연구팀 제시값' |
| 이전·사업화 조건 | 희망 이전 형태(전용·통상실시·공동연구·연구소기업)·추가 개발 기간·공급 형태 | 통상실시 + 공동 PoC 1년, PCB 모듈 공급 |
| 입력 자료의 지위 | 의뢰인이 준 계획서·양식·전년판·발표자료를 어떻게 다루나 — 입력('우리 제품이 무엇인가') / 기준선(전년판) / 기존 수치 전량 폐기. 의뢰인 자료의 수치도 원문 쪽번호 대조 후 사용(회의록 판독 에이전트가 성과 수치를 오기한 사례) | 기술소개서는 입력, 양식 기재 수치는 전량 폐기 후 재조사 |
| 넣지 않는 것 | 독자 사정으로 제외하는 것 | 연구팀 미공개 성능값, 특정 참여기관 언급 |
| 독자 테스트 질문 | G4 에서 던질 1~3개 질문 | "기업 담당자가 10분 읽고 상사에게 한 문장으로 전달할 수 있나" |

## 독자 유형 프리셋 (실사례 — 해당 행을 골라 위 표를 채운다)
| 유형 | 설득 대상 → 결정 | 핵심 메시지가 답해야 할 것 | 비교 기준 | 실사례 |
|---|---|---|---|---|
| 기술이전 희망 연구자(조사유형 = 기술사업화 실사: 기술성·권리성·시장성·사업성) | 수요기업 → 기술이전 검토 착수 | 시장이 실재·성장하고, 기존 대안 대비 이 기술이 푸는 문제가 구체적이며, 도입 기업이 얻는 것이 수치로 보임 | 기존 대안·경쟁 제품, 기업의 도입 비용·인증 부담 | 출연연 EH-PMIC BM(논지 2회 교체: 단가 프리미엄 → TCO 제거 → 사용자 확정 '충전 주기 연장') |
| 예비창업자·창업팀 | 투자자·본인 → 사업 착수·입증 과제 | 우리 접근이 경쟁 지형 어디에 서고 무엇을 입증해야 하나. 팀 수치 없이 접근 방식만 비교축 | 경쟁 기술의 공개 수치 | 촉매 저감 문헌조사(v3 창업자 관점) |
| 사업화 주관기관·컨소시엄 | 경영진 → 어디서 먼저 사업하나 | 경쟁사 대비 강약점 → 시장·규제(국내·해외) → 진출 순서 | 경쟁사·나라별 시장. 계획서는 입력일 뿐 평가 대상 아님 | 체외진단 사업화 용역(v15 진출지 결정) |
| 연간 업데이트 독자(두 층) | 전년 독자 + 신규 독자 → 변화 파악 | 전년 기준선·올해 변화·전년 결론 판정이 한 본문에서(별도 트랙 없이 병기 문형) | 전년판(전문 선열람, 기준선 표) | PEM 2026(작업폴더 `audit/reader-design.md`) |
| 기관 내부 기술사업화 판단 | 자기 조직 → 진입 시장·파트너·타이밍 | 사업화 기술이 들어갈 시장과 주체의 변화 | 1차 DB·공시 | PEM 2026 의사결정 용도 |

## 핵심 메시지 운용 규칙
1. **가설이다.** 축별 `audit/intent-diff.md`("메시지가 참이라면 축마다 무엇이 관측돼야 하나 / Fails if")의
   모근. 축 도출 체인은 `독자·목표(핵심 메시지) → 의사결정 용도 → 조사질문 → 축 → 에이전트 → 3부 챕터`.
2. **반증되면 교체하고 기록한다.** Fails-if 가 촉발되면 사용자 확정으로 메시지를 교체한다. §0 은 승인 시점 가설로
   동결(G0 해시 결박 — 고치면 [2]·G4 가 드리프트로 실패)하고, 교체 메시지는 `intent-diff.md` 맨 위 `현행 메시지:` 줄에
   폐기/채택 병기로 둔다. 워커 `0.` 줄·[3] 핵심어 검사·1부 판정은 그 줄 기준(없으면 §0). 금지 서술 목록(출연연 BM: "단가
   프리미엄"·"TCO 제거")도 그 줄 아래 두고 [3] 뒤 원고 전체 grep 0건을 확인한다 — 폐기한 옛 양식 주장이 워커 산출물로
   되돌아온 사례.
3. **모든 장은 핵심 메시지로 귀결된다.** [3] 작성 후 요약·각 장·10부 권고가 '독자의 결정'에 답하는지 점검.
   기계 보조: 메시지의 핵심어(대상 기술명·비교축 명사)가 요약과 각 장에 최소 1회 등장(촉매 저감 조사 v2 는
   '굴곡도' 0회). 권고는 독자가 결정할 형태("국내 먼저 → 일본·미국 병행 후보")로 끝낸다.
4. **포함 기준 = 독자가 결정에 쓰는가.** 쓰지 않는 자료는 부록 또는 삭제(PEM 리뷰 코멘트 #5 "연구자에게
   참고될 자료가 아님", #16 "너무 세부적"). 사실 검증을 통과했다는 것은 포함 이유가 아니다.
5. **워커에게 전달한다.** 스폰 메시지 `0.` 줄 서식은 `agent-briefs.md`.

## 관점·말투 규칙 (납품 원고 공통 — 위반 사례가 있는 것만)
- 주어는 '보고서 관점' 필드대로. 입력 자료·계획서를 평가 대상으로 삼는 말투("계획서는 ~ 기재", "성립하지 않음/통과할
  수 있음") 금지 — 사실은 유지하고 **전략 문장**으로("기존 제품이 선점 → 연속 추이로 차별화"). 조사 결과에 붙이는
  `(평가)`·`(종합)` 라벨은 `mdr-hwpx/references/deliverable-rules.md` §1 대로 허용.
- 입력 자료의 내부 불일치는 지적 목차를 세우지 않고 해결 방향으로("두 경로로 구상됨 → 한 곳 지정이 선결 과제").
- 자료명을 주어로 쓰지 않는다 — "<주체>의 자료에 따르면". '조사팀·워커·대장·웨이브·확인 범위' 등 작업 흔적 금지.
- 경쟁 범위가 정의에 따라 갈리면 두 범주를 나란히 기재한다. 어느 쪽을 경쟁으로 볼지는 독자(기업) 판단.
- 근거 등급 단서('본문 확인'·'미확정'·'확인 범위에서')는 문장마다 붙이지 않고 조사 방법 1문장 + 표 `* 주 :` 로
  모은다 — 지우는 것이 아니라 한곳으로 모으는 것.

## G4 독자 테스트 (intent-diff 축별 대조와 함께, 결과는 `intent-diff.md` 에 추기)
1. **1차 독자 테스트**: 요약(권두 2쪽)만 읽고 '독자의 결정'을 내릴 수 있나.
2. **설득 대상 테스트**: 2차 독자가 던질 첫 반박("그래서 우리가 왜 사야 하나", "경쟁사도 하지 않나")에 답하는
   절이 있나. 반박을 미리 흡수하는 근거(실패 사례·업계 회의론)가 9부에 있나 — 없으면 `intent-diff.md` 에 '반박 근거
   미발견'으로 남긴다(9부는 근거 있을 때만).
3. **신규 독자 테스트**: 임의 절 단독 열람 시 기관 정체·용어·전년 맥락이 절 안에서 복원되나(괄호 풀이가 아니라 문장으로).
4. **핵심 메시지 귀결**: 운용 규칙 3 의 핵심어 검사 + 10부 권고 형태.
5. **시각화·인쇄 가독성**: 수치 데이터는 그림 우선(`visual-first.md`, `visual_audit.py` 미결 0건); ❍ 머리 70자·하위
   불릿 3개 이하, 산문 나열은 표 또는 그림(기준은 `image-research.md`). 캡처·도판은 팀리드가 눈으로 연다.
실패 시 복귀: 1·2·4 는 [3] 보고서 작성(장이 메시지와 무관한 일반론으로 흐른 경우) — 근거 자체가 비면 [E] 확장.
