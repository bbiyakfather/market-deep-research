# hwpx-form — 원고 md → 발주처 양식 HWPX 변환 모듈 설계 노트

발주처가 준 「보고서 양식.hwpx」 그대로인 한글 문서를 원고에서 자동 생성하기 위한 실측 지식.
2026년 내비온 PEM 수전해 보고서에서 **실제로 빌더를 만들고 한글로 출력해 확인한** 값만 적는다.

**모듈화의 축** — 아래를 반드시 갈라서 다룬다. 섞으면 다른 발주처 양식에서 그대로 깨진다.
- **[양식별]** 양식 파일을 열어 매번 실측해야 하는 값 (ID·판형·폭)
- **[공통]** HWPX 포맷 자체의 규칙. 어느 양식에서도 같다 — 모듈 코드에 상수로 박아도 되는 것

---

## 기본 전략 — 양식을 템플릿으로 쓴다 [공통]

스타일을 코드에서 정의하지 않는다. 양식 파일의 `Contents/header.xml`(글꼴·글자모양·문단모양
정의 전부)을 **통째로 복사**하고 `Contents/section0.xml` 만 원고로부터 새로 조립한다.
빌더는 "어떤 ID를 어디에 쓸지"만 안다. 양식이 바뀌면 양식 파일을 갈아끼우고 ID 상수만 다시 맞춘다.

```
양식.hwpx ─┬─ header.xml    → 그대로 복사 (+ 필요한 charPr 한두 개만 덧붙임)
           ├─ section0.xml  → secPr(판형)만 떼어내고 본문은 버림
           └─ 나머지        → 그대로 복사 (BinData 는 버리고 원고 그림으로 교체)
```

`secPr`(용지·여백)은 **첫 문단의 첫 run 안에** 넣어야 한다. 별도 문단으로 두면 한글이 무시한다.
줄 배치 정보(`linesegarray`)는 넣지 않는다 — 한글이 열면서 다시 계산한다(정상 동작).

`content.hpf` 의 그림 등록부(`<opf:item id="image*">`)를 원고 그림으로 교체해야 하고,
각 항목에 `hashkey`(파일 MD5 의 base64)가 필요하다.

`secPr` 의 `pagePr`/`margin` 에서 읽는다. 아래는 내비온 양식 실측값(A4 세로).

| 항목 | HWPUNIT | 환산 |
|---|---|---|
| 용지 | 59528 × 84186 | A4 |
| 좌·우 여백 | 5669 | 20mm |
| 상·하 여백 | 4252 | 15mm |
| 머리말·꼬리말 | 2835 | 10mm |
| **본문 폭** | 48188 | 용지폭 − 좌우여백. 표·그림 최대 폭 |
| **본문 높이** | 70012 | 용지높이 − 상하여백×2 − 머리말·꼬리말×2 |

본문 높이는 표가 한 쪽을 넘는지 판정할 때 쓴다. 단위는 HWPUNIT = 1/7200 inch.

## 글자·문단 ID 매핑 [양식별]

원고 마크다운 문법 → 양식 header.xml 의 정의 ID. **이 표가 양식마다 다시 만들어져야 할 부분이다.**

| 원고 표기 | 역할 | charPr | paraPr | 글꼴 | 크기 | 굵기 | 정렬 | 좌여백 | 줄간격 |
|---|---|---|---|---|---|---|---|---|---|
| `# 제목` | 부 제목 | 23 | 46 | 휴먼명조 | 20pt | B | LEFT | 0 | 160% |
| `## 1.` | 1단계 | 24 | 47 | 휴먼명조 | 15pt | B | JUSTIFY | 500 | 160% |
| `### 1.1` | 2단계 | 25 | 48 | 휴먼명조 | 14pt | B | JUSTIFY | 800 | 150% |
| `#### `, `① ` | 3단계 | 26 | 49 | 휴먼명조 | 13pt | B | JUSTIFY | 1000 | 120% |
| `❍ 본문` | 본문 1단 | 27 | 50 | 휴먼명조 | 12pt | – | JUSTIFY | 1000 | 160% |
| `- 하위` | 본문 2단 | 29 | 51 | 휴먼명조 | 12pt | – | JUSTIFY | 2000 | 160% |
| 캡션 | 표·그림 공용 | 32 | 52 | 맑은 고딕 | 10pt | – | CENTER | 0 | 150% |
| 표 머리 셀 | | 38 | 55 | 맑은 고딕 | 10pt | **B** | CENTER | – | 130% |
| 표 데이터 셀 | | 35 | 56 | 맑은 고딕 | 10pt | – | CENTER | – | 160% |
| 표 출처행 | | 37 | 57 | 맑은 고딕 | 10pt | – | LEFT | – | 160% |
| 그림·표 담는 문단 | | – | 53 | – | – | – | CENTER | 0 | 160% |

셀 테두리(borderFill)도 **위치별로 ID가 다르다** — 외곽선을 굵게 보이게 하는 구성이다.

| | 첫 열 | 가운데 열 | 끝 열 |
|---|---|---|---|
| 머리행 | 10 | 11 | 12 |
| 데이터행 | 13 | 9 | 15 |
| 출처행 | 16 (전 열 병합) | – | – |

머리행 회색 음영은 borderFill 정의 안에 이미 들어 있다(`<hc:winBrush faceColor="#D9D9D9"/>`).
빌더가 음영을 따로 만들지 않는다 — ID만 참조한다.

### 실측 방법 [공통]

ID를 눈으로 찾지 말고 뽑아낸다. **양식이 "쓰고 있는" 조합만** 세는 게 요령이다(정의는 수백 개라도
실제 사용은 10여 개). 표 내부 문단은 본문과 섞이므로 `<hp:tbl>…</hp:tbl>` 을 지우고 센다.

```python
scope = re.sub(r'<hp:tbl .*?</hp:tbl>', '', section_xml, flags=re.S)
use = Counter(re.findall(r'<hp:p id="\d+" paraPrIDRef="(\d+)"[^>]*>\s*<hp:run charPrIDRef="(\d+)"', scope))
# 이 (paraPr, charPr) 쌍을 header.xml 의 정의와 조인해 글꼴·pt·정렬·여백을 붙인다
```

주의 — `<hh:paraPr>` 의 왼쪽여백은 `<hc:left value="…">` 에 있다. 사람이 손으로 옮겨 적은 표는
믿지 말 것(내비온 form_spec 은 전 항목이 실측의 정확히 2배로 적혀 있었다. ID만 쓰므로 출력에는
영향이 없었지만, 값을 보고 판단하면 틀린다).

## 표 [공통 규칙 + 양식별 폭]

- 폭은 **본문 폭에 맞춘다**(내비온 48178). 캡션은 `side="TOP"`, 그림은 `side="BOTTOM"`.
- 안쪽 여백 `left/right 510, top/bottom 141`, 바깥 여백 사방 141.
- 출처는 표 밖 문단이 아니라 **마지막 행에 전 열 병합**(`colSpan=열수`)으로 넣는다. 위 테두리만
  있는 borderFill 을 쓰면 표에 붙은 주석처럼 보인다.
- `repeatHeader="1"` — 쪽 넘어가면 머리행 반복.

### 열 너비 배분 [공통 — 그대로 재사용 가능]

단순 비례 배분은 **반드시 깨진다**. 서술이 긴 열이 폭을 독식해 짧은 라벨 열이 글자 폭 아래로
눌리고, `구분` 같은 말이 한 글자씩 세로로 쏟아진다. 열별 하한을 내용에서 먼저 정하고 남은 폭만
비례로 나눈다.

```
IN_MARGIN = 1020   # 셀 안쪽 좌우 여백 510+510 — 글자가 쓸 수 없는 폭
COL_UNIT  = 500    # 표시 한 칸(반각) 폭. 10pt 한글 한 글자 = 2칸 = 1000
MIN_COL   = 3300   # 최소 열폭 = IN_MARGIN + 한글 두 글자 + 여유
LABEL_MAX = 12     # 이 칸 수 이하인 열은 "라벨 열"
DATA_CAP  = 30     # 비례 가중치 계산 시 데이터 셀 길이 상한

열별 하한 = clamp(MIN_COL,  (라벨 열이면 최장 셀 전체, 아니면 최장 낱말) × COL_UNIT + IN_MARGIN,  표폭÷2)
열별 가중치 = max(3, 머리글 길이, min(데이터 최장 길이, DATA_CAP))
하한 합 ≥ 표폭 → 하한끼리 비례 축소 / 아니면 → 하한 + (남은 폭 × 가중치 비율)
반올림 오차는 마지막 열이 흡수
```

- **라벨 열은 셀을 통째로 한 줄에** 담는다. 안 그러면 같은 유형 표인데 `정책 입안` 이 어떤 표에서는
  한 줄, 어떤 표에서는 두 줄이 되어 표마다 모양이 달라진다.
- **서술 열은 최소한 낱말이 안 잘릴 만큼**. 이게 없으면 `에너지다변화절약연구소(IDAE` / `)` 처럼
  닫는 괄호만 다음 줄로 떨어진다.
- 글자 폭 환산(`COL_UNIT`)은 근사다. 폰트가 바뀌면 다시 재야 한다.

### 쪽 경계 처리 — 가장 헷갈리는 부분 [공통]

두 속성이 얽혀 있고, **정적 검사로는 절대 못 잡는다**(XML 은 멀쩡해 보인다).

| `treatAsChar` | `pageBreak` | 실제 동작 |
|---|---|---|
| `1` (글자처럼 취급) | 무엇이든 | **쪽 경계에서 안 나뉜다.** 안 들어가면 통째로 다음 장으로 밀림 |
| `0` | `CELL` | 나뉜다. 단 **셀 내부까지 쪼개진다** (`아시아·오세아니아` 가 두 쪽으로 갈림) |
| `0` | `NONE` | 안 나뉜다. 개체 배치라 앞뒤 본문이 더 촘촘히 흐름 |

`treatAsChar="1"` 인 표가 한 쪽을 넘으면 **들어갈 자리가 영영 없어** 앞 쪽 아래가 통으로 빈다
(실측: 42쪽 중 7쪽, 최대 12.7cm). 그래서 **표 높이를 어림해 한 쪽을 넘는 표만 `0` 으로 푼다.**

```
행 줄 수 = max over 셀( ceil(_disp_len(셀) × COL_UNIT / (열폭 − IN_MARGIN)) )
행 높이  = 줄 수 × (머리행 1300 | 데이터행 1600) + 282   # 줄높이 = 10pt × 줄간격, 282 = 상하여백 141×2
표 높이  = Σ 행 높이 (+ 출처행)      →  본문 높이(70012) 초과 시 treatAsChar="0"
```

조판 높이와 정확히 같을 필요는 없다 — "한 쪽을 넘는가" 판정만 하면 된다.

## 그림 [공통]

**가장 값비싼 함정 하나.** `imgClip`(원본 중 잘라 쓸 영역)은 **표시 크기가 아니라 원본 이미지
좌표계**다. 단위는 `픽셀 × 75`(= 7200/96dpi).

여기에 표시 폭을 넣으면 원본의 그만큼만 잘라 프레임에 늘려 그린다 → **확대·크롭된 그림**이 나온다.
1433px 원본(=107,475)에 48,188 을 넣어 44%만 보였던 사고가 실제로 있었다.

```
org_w, org_h = px_w * 75, px_h * 75
orgSz   = org_w, org_h        # 원본 좌표계
imgRect = 0,0 ~ org_w, org_h  # 원본 좌표계
imgClip = 0, org_w, 0, org_h  # 원본 좌표계 — 전체를 쓴다
curSz   = w, h                # 표시 크기 (본문 폭에 맞춘 값)
sz      = w, h                # 표시 크기
```

- 배치는 `treatAsChar="1"`, `textWrap="TOP_AND_BOTTOM"`.
- 세로로 긴 그림은 높이 상한(한 쪽을 넘지 않게)을 걸고 폭을 역산한다.
- 표시 폭을 본문 폭 100% 로 할지는 **취향이다.** 완성본은 중앙값 81% 였다(도판마다 제각각).
  100% 는 도판 안 글씨가 작아지지 않아 안전한 기본값이고, 개별 조정은 한글에서 직접 하면 된다.

## 검증 — 정적 검사는 검증이 아니다 [공통]

XML 이 스키마에 맞아도 크롭·세로쏟아짐·쪽 밀림은 전부 통과한다. **한글로 출력해서 봐야 한다.**

```python
# 한글 COM → PDF. Hwp.exe 가 안 떠 있으면 CoCreateInstance 가 "서버 실행에 실패" 로 죽는다.
#   → Start-Process "…\HOffice130\Bin\Hwp.exe" -ArgumentList "-Automation" 로 먼저 띄운다
import win32com.client as w
h = w.gencache.EnsureDispatch("HWPFrame.HwpObject")
h.RegisterModule("FilePathCheckDLL", "FilePathCheckerModule")   # 없으면 보안 대화상자에서 멈춘다
h.Open(src, "HWPX", "forceopen:true")
h.HAction.GetDefault("FileSaveAsPdf", h.HParameterSet.HFileOpenSave.HSet)
h.HParameterSet.HFileOpenSave.filename = out
h.HParameterSet.HFileOpenSave.Format = "PDF"
h.HAction.Execute("FileSaveAsPdf", h.HParameterSet.HFileOpenSave.HSet)
h.Quit()
```

`.hwp`(바이너리) 를 읽어야 할 때도 같은 방법으로 `h.SaveAs(out, "HWPX")` 해서 XML 로 만든 뒤 판다.

낸 PDF 를 PyMuPDF 로 **자동 채점**한다. 눈으로 41쪽을 다 보는 건 불가능하고, 아래 네 지표가
실제 결함을 전부 잡아냈다.

| 지표 | 방법 | 정상 |
|---|---|---|
| 그림 크롭 | PDF 내장 이미지 종횡비 vs 원본 종횡비 | 오차 2% 이내 |
| 낱말 잘림 | 열별 `최장 낱말 × COL_UNIT` vs `열폭 − IN_MARGIN` | 초과 0건 |
| 표 쪽걸침 | 캡션(`<표>`) 없이 긴 가로선이 여러 개인 쪽 | 의도한 큰 표에서만 |
| 여백 낭비 | 쪽별 `본문하단 − 마지막 요소 y` | 3.5cm 초과 쪽 최소화 |

그 다음 **의심 쪽만 골라 이미지로 렌더해 눈으로 본다**(`page.get_pixmap(dpi=90)`).
