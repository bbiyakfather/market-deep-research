## 2. 시스템별 한 단락

**Anthropic 다중 에이전트 [열람].** 리드(Opus 4)가 계획하고 서브에이전트(Sonnet 4)를 병렬로 띄운 뒤 종합. 내부 평가에서 단일 Opus 4 대비 +90.2%. BrowseComp 성능 분산의 80% 를 토큰 사용량이 설명, 멀티에이전트는 채팅의 약 15배 토큰. 우리에게 가장 가치 있는 것은 "지시문 4요소"와 "노력 규모 규칙"과 "계획을 외부에 저장". 평가는 소규모 대표 질의 + LLM 심판 + 사람 테스트의 조합. 사람 테스트에서 SEO 콘텐츠팜 선호가 발견되어 출처 품질 휴리스틱을 넣었다고 함.

**STORM / Co-STORM [열람 초록].** 관점 발굴 -> 관점별 질문 -> 근거 있는 답변 -> 개요. 질의 다양성을 구조적으로 만드는 방법이며 우리 병렬 워커 분할(대상별·주제별)에 "관점별" 축을 하나 더 얹는 용도로 쓸 수 있다. Co-STORM 은 사용자 개입형이라 우리와 거리가 있음. 전문가 편집자가 지적한 한계(출처 편향 전이, 무관한 사실의 과잉 연결)는 우리 재검증 단계가 일부 막아줌.

**GPT-Researcher [열람].** 플래너가 하위 질문 생성 -> 질문별 실행 에이전트가 크롤·요약·출처 추적 -> 퍼블리셔가 취합. 본문을 LLM 에 넣기 전 컨텍스트 필터(Jev/BM25/임베딩)를 둔 점, 트리형 재귀 딥리서치(깊이·폭)가 특징. 필터 평가는 자사 측정이며 28과제로 작다.

**open_deep_research [열람].** 스코프(명확화 -> 브리프) -> 슈퍼바이저 + 독립 컨텍스트 서브에이전트 -> 단일 호출 보고서 작성. 레포는 보관(archived)됨. DeepResearch Bench RACE: 기본 0.4309, GPT-5 연구 모델 0.4943, 제출본 0.4344(2025-08 기준 6위). 비용 100과제당 약 $20~100. 교훈은 "병렬은 조사에만, 작성은 한 번에".

**OpenAI Deep Research [검색만].** 공식 페이지는 403 으로 못 열었음. 2차 보도에 따르면 OpenAI 가 인정한 한계: 환각·잘못된 추론, 권위 있는 정보와 소문 구분 어려움, 확신도 보정 미흡. 출력에 인용과 사고 요약 포함. 기법 상세(강화학습 등)는 [미확인]. BrowseComp 논문(arXiv 2504.12516)은 [검색]만: 1,266문항, 브라우징 모델의 과신을 지적. 수치(Deep Research 51.5% 등)는 2차 요약이라 원문 대조 필요.

**Gemini Deep Research [검색만].** 계획 수립 -> 사용자 수정 -> 순차/병렬 하위과제 판단 -> 수집 결과를 보고 다음 행동 결정 -> 종합. 내부 기법·수치는 공개 자료에 없음.

**Perplexity Deep Research [열람].** 검색·열람·추론 루프에서 계획을 수정하며 진행, 2~4분. HLE 21.1%, SimpleQA 93.9%. 재현율·인용 정확도 수치는 없음.

**Exa [열람, LangChain 사례 경유].** 플래너 -> 병렬 태스크(각자 JSON 스키마 출력) -> 옵저버. Exa 자체 블로그는 404 라 [미확인]. 스니펫 우선 추론, 태스크 간에는 정제된 최종 출력만 공유.

**Tavily [열람].** 증류된 반성 중심의 선형 토큰 증가, 전역 출처 중복 제거, 범위 협소화 감지. "평가 점수 단독 최적화 안 함, 에이전트 추적 모니터링이 더 유익"이라는 태도. 리더보드 수치는 Tavily 블로그에 없고 제3의 논문 [검색]에 tavily-research 52.44 / gemini-2.5-pro-deepresearch 49.71 / openai-deep-research 46.45 로 인용됨(원문 [미확인]).

**Firecrawl research 계열 [미확인].** 크레딧 소진으로 열람 못 함. 이번 조사에서 근거 없음.

## 3. 평가 방법 요약

- **DeepResearch Bench [검색]:** 100과제(영 50/중 50), 22분야. RACE(보고서 품질, 심판 Gemini-2.5-pro) + FACT(인용). FACT 의 핵심은 "인용 정확도"와 "유효 인용 수"를 분리한다는 점. 정확도만 높고 유효 인용이 적은 시스템이 존재 -> 정밀도만 재면 재현율 약점이 숨는다(우리 상황과 정확히 겹침).
- **WideSearch [열람]:** 목록 전수 수집 평가. 정답 표를 사람이 만들고 Row/Item F1 로 재현율 측정. 정답지 구성 방식(원자 사실 단위 검증 가능한 표)이 그대로 쓸 만함.
- **BrowseComp [검색]:** 짧고 검증 쉬운 정답, 끈질긴 탐색 능력 측정. 장문 보고서·모호한 질의는 범위 밖.
- **LLM 심판의 한계:** 약한 심판의 보상은 강한 패널로 전이되지 않음 [검색], 인용 검증 정확도가 검색 깊이 2->150호출에서 약 42% 하락한다는 주장 [검색, 원문 미확인], 쌍대 선호는 시스템 단위 평가에만 적합하고 지표 단위에는 전문가 주석이 필요 [열람 초록 https://arxiv.org/abs/2603.06942], 딥리서치는 환각보다 주제 이탈이 흔해 관련성 지표를 별도로 둬야 함 [검색].
- **다국어:** XBCP(arXiv 2606.15345) [검색]는 증거가 12개 언어에 흩어지면 재현율과 보정이 크게 떨어진다고 보고. 다국어 질의 확장이 커버리지를 올린다는 근거는 찾지 못함 [미확인]. 따라서 한/영 병행 질의는 "효과 입증됨"이 아니라 "도메인 직관"으로 취급해야 함.

## 4. 우리에게 옮길 후보 순위

가정: 우리 약점은 재현율·출처 다양성·반복 루프. 정밀도는 이미 강함.

1. **공백 진단 -> 재조사 루프 + 증거 충분성 종료 기준** (Open Deep Research 슈퍼바이저 검토, "Don't Stop Early", WideSearch 실패 분석). 비용: 문서 수정 + 소규모 코드(종료 판정 체크리스트). 효과 수치 없음이나 WideSearch 가 "실패 후 포기·불완전 분해"를 주 실패 원인으로 실측함. 최우선.
2. **목록형 질문의 전수 열거 절차** (WideSearch 진단 + 멀티에이전트 분할 우위). 대상 목록을 먼저 만들고 대상별 워커, 검색 0건이면 "미확인"으로 표기(날조 금지), 서로 다른 워커가 같은 목록을 독립 재수집해 합집합·차집합 대조. 비용: 문서 수정만 -> 소규모 코드. 128회 반복 시 Item F1 ~80 이라는 보고는 반복 수집의 재현율 효과 근거.
3. **재현율 평가 세트** (WideSearch 의 원자 사실 정답 표 + FACT 의 정확도/유효 인용 분리). 소수 과제(약 20개, Anthropic 권고)에 사람이 만든 정답 목록을 두고 재현율을 재는 회귀 테스트. 비용: 소규모 코드. 이게 없으면 위 1·2 의 개선을 확인할 수 없음.
4. **워커 지시문 4요소 + 노력 규모 규칙** (Anthropic). 비용: 문서 수정만. 즉시 적용 가능, 중복 조사 감소.
5. **재인용·신디케이트 제거와 독립 출처 계수** (deepi-research, Tavily 중복 제거). "서로 다른 도메인이면서 서로 다른 검색 경로에서 나온 출처만 교차확인으로 인정", 제목 유사도 중복 제거. 비용: 소규모 코드. 근거는 개인 프로젝트·벤더 주장이라 효과는 [미검증].
6. **다관점 질문 생성 단계** (STORM). 계획 단계에서 관점 3~5개(예: 규제·고객·경쟁사·기술·회의론자)를 만들어 질의 세트를 확장. 반대 증거 탐색 전용 관점(회의론자)을 넣으면 반대 증거 확보에도 쓰임. 비용: 문서 수정만. 효과 +10% 커버리지는 위키 생성 과제 기준이라 보고서 조사에 그대로 일반화하긴 어려움.
7. **범위 협소화 감지 -> 미탐색 도메인 유도 + 도메인 다양성 강제** (Tavily). 최종 출처 목록의 도메인 편중(예: 상위 도메인 비중)을 계산해 기준 초과 시 재조사 트리거. 비용: 소규모 코드.

차순위: 스니펫 우선 판단(Exa, 토큰 절감용), 컨텍스트 필터 BM25(GPT-Researcher, 무료 폴백 가능), 증류된 반성(Tavily, 컨텍스트 비용 절감), 보고서 단일 호출 작성(이미 그렇다면 보유).

## 5. 옮기지 말아야 할 것

- **대화형 Co-STORM 식 마인드맵/사용자 협업 토론**: 우리는 비대화형 배치이고 이득 근거가 사용자 선호 조사뿐이라 비용 대비 효과가 없음.
- **유료 API 전제 기법 및 단일 LLM 심판 점수를 품질 지표로 삼는 것**: Tavily Advanced Search 같은 벤더 검색층, RACE 류 단독 점수는 의존하면 안 됨. 심판은 약하면 왜곡되고, 인용 정확도만 재면 재현율 결함이 가려진다. 또한 도메인 권위 점수(deepi-research)는 검증된 표준이 아니므로 하드 규칙으로 쓰지 말고 참고 가중치로만.
